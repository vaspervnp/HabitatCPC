# Planetbase — κατάλογος sprites και οδηγός χρήσης

Τι υπάρχει στο `sprites.bin`, σε τι μορφή, και πώς συντίθεται μια οθόνη.
Συνοδεύει το `sprites.asm`· το [README](README.md) λέει από πού προέρχονται
αυτά τα αρχεία και πώς ξαναπαράγονται.

> **Αντίγραφο.** Το πρωτότυπο ζει στο repo `CPCArt` (`planetbase/SPRITES.md`) και
> παράγεται μαζί με τα δεδομένα. Οι αριθμοί εδώ ισχύουν για build με τις
> προεπιλογές (`--quads all`, σφιχτά τεταρτημόρια).

---

## 1. Βασικά

| | |
|---|---|
| Mode | 0 — 160×200, 16 χρώματα, 2 pixels ανά byte |
| Αναλογία | 2:1 — κάθε pixel διπλάσιο σε πλάτος· «οπτικά» = πλάτος ×2 |
| Ευθυγράμμιση | κάθε sprite έχει ζυγό πλάτος και μπαίνει σε ζυγό x (ακέραια bytes) |
| Διάταξη | γραμμικά, γραμμή-γραμμή από πάνω προς τα κάτω — **όχι** διάταξη οθόνης |
| Φόρτωση | το μπλοκ σε διεύθυνση **πολλαπλάσιο του 256** (το `flip_mode0` θέλει σελίδα) |

Διεύθυνση οθόνης: `+#800` ανά γραμμή, και `+#50-#4000` (δηλαδή `-#3FB0`) μετά από
κάθε 8 γραμμές. Τον υπολογισμό τον κάνει η ρουτίνα blit, όχι τα δεδομένα.

Παλέτα: `palette_fw`, 16 firmware colour numbers για pen 0..15. Pen 0 είναι το
φόντο/έδαφος και ταυτόχρονα το **διαφανές** χρώμα στα sprites με μάσκα.

## 2. Οι δύο μορφές sprite

**Με μάσκα** — `mask, data, mask, data…` ανά γραμμή, ώστε ο Z80 να διαβάζει
διαδοχικά με `HL`:

```
ld a,(hl) : inc hl : and (de) : ld b,a
ld a,(hl) : inc hl : or b     : ld (de),a : inc de
```

**Αδιαφανή** — μόνο `data`· ένα `ldi`-στυλ αντίγραφο ανά γραμμή.

> **Το πιο εύκολο λάθος.** Όλες οι σταθερές `*_W` δίνουν bytes **δεδομένων** ανά
> γραμμή, δηλαδή `πλάτος_σε_pixels / 2`. Σε sprite **με μάσκα** η γραμμή
> καταλαμβάνει **2× αυτό**, γιατί mask και data είναι πλεγμένα:
>
> ```
> stride = W          αδιαφανές
> stride = W * 2      με μάσκα
> μέγεθος = stride * H
> ```
>
> Π.χ. `DOME_L_W=16`, `DOME_L_H=64` → γραμμή 32 bytes, σύνολο 2048 (`DOME_L_SZ`).
> Ενώ `MACH_W=6`, `MACH_H=22` → γραμμή 6 bytes, σύνολο 132 (`MACH_SIZE`).

| Μορφή | Ποια sprites | Γιατί |
|---|---|---|
| μάσκα | θόλοι, δακτύλιοι, διάδρομοι, σημεία σύνδεσης, εξωτερικές δομές | στρογγυλά σχήματα που συντίθενται μεταξύ τους |
| αδιαφανή | εικονίδια, μηχανές, φυτά, θέσεις αποίκων | κάθονται πάντα πάνω σε γνωστό φόντο |

Τα αδιαφανή είναι το μισό σε bytes και το μισό σε χρόνο. Γι' αυτό ό,τι ξέρουμε ότι
πατάει σε σταθερό φόντο δεν παίρνει μάσκα.

## 3. Θόλοι και δακτύλιοι

Τρία μεγέθη. Ο θόλος και ο δακτύλιος είναι **ξεχωριστά** sprites — ο δακτύλιος δεν
περιέχει τον θόλο — και το καθένα κομμένο σε 4 τεταρτημόρια.

| Μέγεθος | Οπτική διάμετρος | Τεταρτημόριο (px) | `_W` | `_H` | γραμμή | `_SZ` |
|---|---|---|---|---|---|---|
| `s` | 48 | 16×32 | 8 | 32 | 16 bytes | 512 |
| `m` | 80 | 24×48 | 12 | 48 | 24 bytes | 1152 |
| `l` | 112 | 32×64 | 16 | 64 | 32 bytes | 2048 |

Σταθερές: `DOME_{S,M,L}_W/H/SZ`. Ο δακτύλιος έχει ακριβώς τις ίδιες διαστάσεις.

Ετικέτες: `dome_{s,m,l}_{nw,ne,sw,se}` και `ring_{s,m,l}_{nw,ne,sw,se}`.

Τα τεταρτημόρια μπαίνουν στο πλήρες πλαίσιο ως:

```
nw (0, 0)          ne (QW, 0)
sw (0, QH)         se (QW, QH)
```

όπου `QW` το πλάτος τεταρτημορίου σε bytes και `QH` οι γραμμές του.

### Με `--quads nw`

Αποθηκεύεται μόνο το `nw`· τα άλλα τρία παράγονται τη στιγμή του blit:

| | |
|---|---|
| `ne` | αντίστροφη σειρά **ΖΕΥΓΩΝ** `(mask,data)` σε κάθε γραμμή, κάθε byte μέσα από το `flip_mode0` |
| `sw` | οι γραμμές με αντίστροφη σειρά, bytes ως έχουν |
| `se` | και τα δύο μαζί |

Το ζεύγος `(mask, data)` μένει ενιαίο: αντιστρέφονται τα ζεύγη, **όχι** τα
μεμονωμένα bytes. `flip_mode0` είναι 256 bytes σε σελίδα, οπότε:
`ld h,flip_hi : ld l,a : ld a,(hl)`.

## 4. Εσωτερικό θόλου

### Εικονίδιο τύπου δωματίου

Κλιμακώνεται με τον θόλο. Οκτώ τύποι, με τη σειρά του `R_TYPE`:

`0 empty · 1 control · 2 quarters · 3 canteen · 4 oxygen · 5 greenhouse · 6 storage · 7 airlock`

| Θόλος | Εικονίδιο | bytes | Δείκτης |
|---|---|---|---|
| `s` | 12×12 px | 72 | `room_icons_s + type*ICON_S_SZ` |
| `m` | 16×16 px | 128 | `room_icons_m + type*ICON_M_SZ` |
| `l` | 20×20 px | 200 | `room_icons_l + type*ICON_L_SZ` |

Θέση: `interior_ofs + size*2` → `(dx σε bytes, dy σε γραμμές)`, **προσημασμένα**,
από το **κέντρο** του θόλου. Στον μεγάλο θόλο το εικονίδιο πάει στο κέντρο και τα
μηχανήματα περιμετρικά· στους άλλους δύο από πάνω τους.

### Μηχανές και φυτά

Ίδιο μέγεθος, ίδιες υποδοχές: **12×22 px** (6×22 bytes, 132 bytes), αδιαφανή.
Ένας θόλος-θερμοκήπιο γεμίζει τις θέσεις του με φυτά αντί για μηχανές.

| | Πλήθος | Δείκτης | Σταθερά |
|---|---|---|---|
| μηχανές | 10 | `machines + type*MACH_SIZE` | `MACH_TYPES` |
| φυτά | 12 | `plants + type*PLANT_SIZE` | `PLANT_TYPES` |

**Μηχανές** (σειρά): `oxygen, iron, bioplastic, weapons, processors, robots, food,
spares, medical, vitromeat`.

`machine_rules + type` → bitmask επιτρεπτών μεγεθών (`bit0=s`, `bit1=m`, `bit2=l`).
Σήμερα μόνο το `oxygen` έχει `1` — μπαίνει μόνο σε μικρό θόλο· όλα τα άλλα `7`.

**Φυτά** (σειρά): `peas, rice, potatoes, wheat, maize, tomatoes, lettuce, onions,
radishes, mushrooms, medicinal, tree`.
`plant_class + type` → `0 starch · 1 veg · 2 medicine · 3 morale`.

**Θέσεις**: `machine_count + size` → πόσες έχει το μέγεθος (**1 / 4 / 8**).
`machine_slots + size*MACH_SLOTS*2 + slot*2` → `(x σε bytes, y)` μέσα στο πλαίσιο
του θόλου. Οι αχρησιμοποίητες θέσεις είναι `255,255`.

## 5. Άποικοι — στους διαδρόμους

Οι άνθρωποι **δεν** είναι μέσα στον θόλο· στέκονται πάνω στον δακτύλιο, σε 8 θέσεις
μετατοπισμένες κατά 22,5° ώστε να μην πέφτουν σε πόρτα.

Κάθε θέση είναι 4×8 px (`SLOT_W=2`, `SLOT_H=8`, αδιαφανής → 16 bytes) σε **δύο
παραλλαγές**, κομμένες από το σύνθετο
πλαίσιο θόλου+δακτυλίου:

```
corr_slot_gfx + size*SLOT_BANK + slot*SLOT_STRIDE + (0 = κενή | SLOT_SIZE = με άποικο)
corr_slots    + size*CORR_SLOTS*2 + slot*2   -> (x σε bytes, y)
corr_fill                                     -> σειρά γεμίσματος: 0,4,2,6,1,5,3,7
```

Η κενή παραλλαγή επαναφέρει **ακριβώς** ό,τι υπήρχε εκεί, οπότε ένα αδιαφανές blit
αρκεί και για να εμφανιστεί και για να **σβηστεί** ένας άποικος — χωρίς μάσκα και
χωρίς να ξαναζωγραφιστεί ο δακτύλιος. Η σειρά `corr_fill` είναι σκορπισμένη ώστε
οι άποικοι να μη φαίνεται ότι στοιβάζονται.

## 6. Διάδρομοι και συνδέσεις

| Sprite | px | `_W` | `_H` | γραμμή | σύνολο | Σημείωση |
|---|---|---|---|---|---|---|
| `corr_h` | 8×8 | 4 | 8 | 8 bytes | 64 | οριζόντιος |
| `corr_v` | 4×16 | 2 | 16 | 4 bytes | 64 | κάθετος |
| `corr_dr` | 16×16 | 8 | 16 | 16 bytes | 256 | διαγώνιος ↘ |
| `corr_dl` | 16×16 | 8 | 16 | 16 bytes | 256 | διαγώνιος ↙ |

Οι διαγώνιοι τοποθετούνται με βήμα `(±CORR_D_SX, +CORR_D_SY)` = `(±4 bytes, +16
γραμμές)`, που είναι 45° οπτικά. Τα tiles **επικαλύπτονται κατά 8 pixels** και η
μάσκα κλείνει τη σκάλα που θα άφηναν εφαπτόμενα tiles — μη τα βάλεις εφαπτόμενα.

**Σημεία σύνδεσης**: `conn_{n,ne,e,se,s,sw,w,nw}` — 4×8 px, `CONN_W=2`, `CONN_H=8`,
γραμμή 4 bytes (με μάσκα), 32 bytes το καθένα. Είναι
κομμάτια του ίδιου του διαδρόμου, οπότε τοιχώματα και δάπεδο συνεχίζουν χωρίς
ασυνέχεια εκεί που ο διάδρομος συναντά τον δακτύλιο.

```
conn_points + size*CONN_DIRS*2 + dir*2   -> (x σε bytes, y) μέσα στο πλαίσιο θόλου
```

Σχεδίασέ τα **μετά** τον δακτύλιο: ανοίγουν την πόρτα πάνω του.

## 7. Εξωτερικές δομές

Αυτοτελή κτίσματα στο έδαφος — **όχι** μηχανές θόλου. Με μάσκα, σε κάτοψη.

| Δομή | Μεγέθη | Ετικέτες |
|---|---|---|
| `solar` | 4 | `solar_s`, `solar_m`, `solar_l`, `solar_xl` |
| `turbine` | 3 | `turbine_s/m/l` |
| `collector` | 3 | `collector_s/m/l` |
| `extractor` | 3 | `extractor_s/m/l` |
| `mine` | 1 | `mine` |

Μεγέθη σε pixels: `s` 8×16, `m` 16×32, `l` 24×48, `xl` 32×64 — όλα **οπτικά
τετράγωνα** (16×16 έως 64×64). Το ορυχείο υπάρχει μόνο στο μεγάλο.

```
struct_dims + kind*8 + size*2  -> (w σε bytes, h σε γραμμές)· 0,0 = δεν υπάρχει
kind: 0 solar · 1 turbine · 2 collector · 3 extractor · 4 mine
```

## 8. Σειρά σχεδίασης ενός θόλου

```
1. ring_{size}_{nw,ne,sw,se}      δακτύλιος   (μάσκα)
2. dome_{size}_{nw,ne,sw,se}      θόλος       (μάσκα)   — δεν επικαλύπτονται
3. conn_{dir} σε conn_points      οι πόρτες, μόνο όπου υπάρχει διάδρομος
4. room_icons_{size} + type       εικονίδιο τύπου, στο interior_ofs
5. machines | plants σε machine_slots
6. corr_slot_gfx σε corr_slots    άποικοι και ρομπότ
```

Τα 1 και 2 δεν επικαλύπτονται ποτέ, οπότε η σειρά τους είναι αδιάφορη. Τα 3-6
πατάνε πάνω στα προηγούμενα.

### Τι ξανασχεδιάζεται όταν αλλάζει τι

Αυτό είναι το σημείο που κρίνει την ταχύτητα — μη ξαναχτίζεις τον θόλο για τίποτα:

| Αλλαγή | Ξανασχεδίασε |
|---|---|
| μπαινοβγαίνει άποικος ή ρομπότ | **μόνο** μία θέση — 16 bytes αδιαφανή |
| αλλάζει/χαλάει μηχάνημα | μία υποδοχή — 132 bytes αδιαφανή |
| μεγαλώνει φυτό | μία υποδοχή — 132 bytes αδιαφανή |
| αλλάζει τύπος δωματίου | το εικονίδιο |
| προστίθεται διάδρομος | το `conn_{dir}` της πλευράς |
| χτίζεται θόλος | όλα, βήματα 1-6 |

## 9. Πίνακες δεδομένων

| Ετικέτα | Μέγεθος | Περιεχόμενο |
|---|---|---|
| `interior_ofs` | 3×2 | θέση εικονιδίου ανά μέγεθος, προσημασμένη, από το κέντρο |
| `machine_count` | 3 | υποδοχές ανά μέγεθος: 1, 4, 8 |
| `machine_slots` | 3×8×2 | θέσεις υποδοχών· 255,255 = κενή |
| `machine_rules` | 10 | bitmask επιτρεπτών μεγεθών ανά μηχανή |
| `plant_class` | 12 | κατηγορία ανά φυτό |
| `conn_points` | 3×8×2 | σημεία σύνδεσης ανά μέγεθος και κατεύθυνση |
| `corr_slots` | 3×8×2 | θέσεις αποίκων ανά μέγεθος |
| `corr_fill` | 8 | σειρά γεμίσματος θέσεων |
| `struct_dims` | 5×4×2 | διαστάσεις κάθε παραλλαγής εξωτερικής δομής |
| `palette_fw` | 16 | firmware colour numbers, pen 0..15 |
| `flip_mode0` | 256 | καθρεφτισμός byte, **σε σελίδα** |

## 10. Μνήμη

Σύνολο **49,2 KB** με `--quads all`, **27,5 KB** με `--quads nw`.

| Κατηγορία | bytes |
|---|---|
| θόλοι | 14.848 |
| δακτύλιοι | 14.848 |
| εξωτερικές δομές | 11.264 |
| εικονίδια δωματίων | 3.200 |
| φυτά | 1.584 |
| μηχανές | 1.320 |
| θέσεις διαδρόμου | 1.920 |
| διάδρομοι | 640 |
| σημεία σύνδεσης | 256 |
| `flip_mode0` | 256 |
| πίνακες + παλέτα | 239 |

Τα τεταρτημόρια είναι 29.696 από αυτά. Με `--quads nw` πέφτουν σε 7.424.

Το [`sprites_map.txt`](sprites_map.txt) έχει offset και μέγεθος για **κάθε** sprite
ξεχωριστά· αυτός ο πίνακας είναι μόνο η σύνοψη.
